# Progress Tracker — La Ideal

**Rule**: Track only what is actionable now. The active sections are:
- **Blocking Issues** — must-fix items before merging the current branch and cutting a release. Items move out of here once resolved (into [`completed_milestones.md`](completed_milestones.md)).
- **Open Non-Blocking Issues** — known backlog that does not gate the release but is still worth doing.
- **Backlog (deferred — low value / not currently planned)** — items consciously parked because the effort outweighs the value (or they depend on an external trigger). Not "open work": revisit only if the trade-off changes. Keeps the Open list a real to-do list.

Finished work (and its Archive) lives in [`completed_milestones.md`](completed_milestones.md), not here.

Add new entries at the **top** of the relevant section. Do not keep an "In Progress" list — work in progress lives in the branch and in Blocking Issues if it gates the release.

| `migrateDatabase` hardening: run the one-time repairs once | `src/sql_lite/sql_lite.cpp` (`migrateDatabase`) | Raised 2026-10-19, kept as it is for now. `migrateDatabase` runs ten groups of steps on every start: 13 idempotent `ALTER TABLE`s, the `accounting_closures` set-up, and eight backfills / repairs from 10.9 to 12.0. It takes under a second on the shop DB, so cost is not the issue. The findings: (1) the 10.12 void-date step is not idempotent. A voided garment with neither `fecha_pago` nor `fecha_recogida` gets `fecha_anulacion = NULL` and matches again at every start (the log says "moved the void date ... on 1 voided garments" each time). It should skip such a row, or set the void date it can prove. (2) There is no schema version, so the one-time repairs (10.9, 10.12, 11.0) run forever and would silently "fix" a row that a future bug puts in the same state. (3) `ALTER TABLE` errors are ignored, so a locked or read-only DB looks like "column already exists". (4) Only the closures step runs in a transaction. Proposed: `PRAGMA user_version`, with each one-time repair run once in its own transaction and logged once; keep only the cheap invariant checks (columns, closure index and triggers) at every start; log a real `ALTER` failure. |
