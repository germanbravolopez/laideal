# Review: sql_lite (src/sql_lite/) - before release 12.0

Reviewer: sql_lite module agent. Read-only; nothing built or run. All line numbers are `src/sql_lite/sql_lite.cpp` unless a path is given.

## Summary

- Health: good. SQL is parameterised everywhere; the only concatenation is constant fragments plus identifiers whose callers all pass literals (checked each caller). The closed-quarter guards, "paid row is frozen" guards and the settled-row guard in `updateTicketVerifactuFields` are solid and well tested.
- Main risks: (1) the Contabilidad listings return an empty list when their query fails, so a report could be written and the quarter closed with zero income; (2) `applySettledVerifactuCancellation` leaves the connection open on 4 of 5 paths and dates the cancellation "today" even if that quarter is closed; (3) no DB-level inalterability on `ingresos` (only `accounting_closures` has triggers); (4) several `ingresos` writers live outside sql_lite and skip its guards (Rectificar, PayDialog, PendingSubmits).
- The tracker's "migrateDatabase hardening" is confirmed (the void-date step is non-idempotent, see F7); extended with 6 more points (F8).
- Docs: 14 public functions undocumented in `docs/modules/sql_lite.md`; the quarterIsClosed rows contradict each other; `architecture.md` says "9 verifactu columns" (code adds 13 columns).
- Tests: about 100 test slots, strong on Verifactu/closure/migration; no test at all for ~12 functions (list in section 3), and no test for any DB-failure path.
