# Review: recog_prendas (RecogPrendas, PayDialog, VoidGarmentsDialog) - before 12.0

Read-only review. Nothing built or run. Files: `src/recog_prendas/recog_prendas.cpp` (RP), `pay_dialog.cpp` (PD), `voidgarmentsdialog.cpp` (VD), plus the `sql_lite.cpp` seams they call.

## Summary

- Health: good. The money paths (amount freezing, seq numbering, `pagado='SI'` scoping of AEAT write-backs, closed-quarter guards, late-reply adoption, unmeasured m2) are carefully done and well covered by the e2e bench.
- One High bug in PayDialog: closing it with Esc / the window X while "Enviando a AEAT..." is showing drops the payment locally while AEAT may already hold the invoice, and loses the reply (PD:287-412, no `reject()` guard).
- One High latent data bug in RecogPrendas: only the name search drains the lazy `QSqlQueryModel` before `db.close()`; the phone / date / ticket searches do not, so more than 256 rows are silently cut and the "Importe total" is wrong (RP:556, 566, 588).
- Medium: manual price override can be overwritten by an unchanged-quantity `editingFinished`; reply-time `INVALID_CONFIG` is stored as "Verifactu disabled" (no estado, no error); future / pre-reception payment dates are accepted; zero-total Cobrar is sent to AEAT; background refreshes re-run the typed (unsubmitted) search text.
- Window-level behaviour of Recogida (search modes, pickup, edits, enable states, Anulado lock, print scope) has no test at all; the self-check M2 re-implements an old `LIKE` search instead of using the window.
