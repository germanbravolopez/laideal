# Review: printing (src/printing + qrcodegen integration)

Reviewer scope: `src/printing/*`, vendored `src/third_party/qrcodegen` (integration only), `src/imprimir/imprimir.cpp` as caller, docs `docs/modules/printing.md` and `docs/modules/printer/*.md`, tests `test_escpos`, `test_ticket_preview`, `tests/support/escpospreview.h`, `tests/tools/escpos_preview.cpp`, `tests/ui/block_c.py`, `tests/ui/printer.py`. Read-only; nothing was built or run (one throwaway Python check of the IVA rounding, see F9).

## Summary

- Healthy, small, well-seamed module: pure builder/renderer with exact-byte tests, a real spooler capture in UI smoke block C, QR sizing (30-40 mm, whole dots) guarded by tests. Decimal comma is correct on every printed amount.
- Main legal concern: the factura simplificada never prints its date of expedicion (it prints "Recepcion"), while the QR encodes `fecha_pago`; and a "Factura completa" is still headed "FACTURA SIMPLIFICADA". Both need the compliance auditor's call before 12.0.
- One real encoding bug: U+00CC (I grave) maps to 0xDD (a broken bar in CP850/858; correct is 0xDE). The test decoder (`escpospreview.h`) repeats the same wrong value, so every test is circular for the code page.
- Printer-offline handling relies on the optional Status API; with the default RAW path an off/unplugged printer is accepted by the spooler and the UI says "impreso". Docs 04/05 and parts of printing.md are stale (Excel-era).
- Test gaps: no tests for ThermalPrinter error paths, `Imprimir::printTicket` branches, 58 mm renders, control-character input, code-page table completeness, wrapping edge cases.
